## 2. Coverage and gaps

### What was actually scanned

- **gitleaks (parent history):** all parent-repo commits (`--all`).
- **gitleaks (dir):** current working tree after `git submodule update --init --recursive`.
- **semgrep:** parent-repo **git-tracked** files only (164). Languages with rules applied: HTML (7), JSON (4), YAML (2), bash (2), Python (1), Lua (1), plus multilang. Layout overrides under `layouts/` were included.
- **osv-scanner:** recursive walk; only extract was `themes/hugo-theme-stack/go.mod` (module path `github.com/CaiJimmy/hugo-theme-stack/v3`, **no `require`**, no `go.sum`).

### Gaps (do not treat “0 vulns / 0 leaks” as full-stack coverage)

1. **No application lockfiles.** There is no `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `requirements.txt`, `Pipfile.lock`, `Cargo.lock`, or `go.sum` in the parent repo. CI has a no-op `npm ci` guard that never runs today.
2. **Hugo and Dart Sass are invisible to OSV.** Deploy installs Hugo extended **0.145.0** via an unverified `.deb` from GitHub Releases, and `sudo snap install dart-sass` (unpinned). Those binaries are the actual site compiler.
3. **Theme and syndicated essays are gitlinks.** Semgrep did **not** scan `themes/hugo-theme-stack/**` or `syndication-sources/social-protocols/**` (0 files). Theme TypeScript (`assets/ts/*.ts`, `search.tsx`) and theme HTML were therefore out of Semgrep’s default git-tracked set.
4. **CDN / runtime JS is not a lockfile.** Live pages load KaTeX 0.16.9 (SRI in the theme) and, when a mermaid fence is present, **unpinned** `cdn.jsdelivr.net/npm/mermaid/dist/mermaid.esm.min.mjs`.
5. **Semgrep parse holes.** Eight warnings: `curl-eval` / `gha-curl-pipe-shell` failed to parse `${{` in `.github/workflows/hugo.yaml`; Go templates in `layouts/*.html` failed HTML parse. Those rules did **not** evaluate the Hugo `wget` + `dpkg` step.
6. **“Files larger than 1.0 MB: 6”** in Semgrep are images/video, not source.
7. **Offline PDF toolchain** (`content/language-design/hermeticity/build-pdf/`, Python + pandoc + LaTeX via `devbox`) has no lockfile OSV can score. It is not on the Pages deploy path (`ignoreFiles: /build-pdf/`).
8. **p/default only.** No secrets pack beyond gitleaks; no Hugo-specific ruleset; no Reachability / call-graph for a static site.

## 4. Findings register

Status values: `open` (advisory). No production change in this PR.

### B-01 — CI deploy supply chain (mutable Actions + unverified Hugo)

| Field | Value |
| --- | --- |
| Severity | Medium |
| Status | open |
| Source | Semgrep `yaml.github-actions.security.github-actions-mutable-action-tag` ×6; manual review of `wget` / snap |
| Evidence | `.github/workflows/hugo.yaml` `uses:` `actions/checkout@v4` (L46), `actions/configure-pages@v5` (L52), `actions/cache/restore@v4` (L57), `actions/cache/save@v4` (L73), `actions/upload-pages-artifact@v3` (L79), `actions/deploy-pages@v4` (L93). Install Hugo: `wget` `hugo_extended_0.145.0_linux-amd64.deb` then `sudo dpkg -i` with **no SHA256**. `sudo snap install dart-sass` unpinned. `actions/checkout` default `persist-credentials: true`. |
| Why it matters | A retagged Action or a swapped GitHub Release asset can run in the job that holds `pages: write` and `id-token: write`. That is enough to publish a trojaned site. Likelihood is lower because these are first-party `actions/*` and a version-pinned Hugo URL, but integrity is not verified. |
| Recommendation (advisory) | Pin each `uses:` to a 40-character SHA. Checksum the Hugo `.deb` against the published checksums file before `dpkg`. Pin Dart Sass. Consider `persist-credentials: false` on checkout (later official Actions do not need the token). Do **not** broaden `GITHUB_TOKEN`. |

### B-02 — Unpinned mermaid CDN on the live origin

| Field | Value |
| --- | --- |
| Severity | Medium |
| Status | open |
| Source | Manual (`layouts/partials/footer/custom.html`) |
| Evidence | `import mermaid from 'https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.esm.min.mjs'` (no version, no SRI), gated by `hasMermaid`. Contrast: theme `data/external.yaml` pins KaTeX **0.16.9** with SRI. |
| Why it matters | Any page with a mermaid fence executes **whatever jsDelivr currently serves** as `mermaid` latest, on `jonathanwarden.com`. That is stored XSS / supply-chain in the browser, independent of Hugo. |
| Recommendation (advisory) | Pin mermaid to a version + SRI (or vendor it into `assets/`). Until then, treat mermaid pages as a higher-trust surface. |

### B-03 — Goldmark `unsafe: true` and raw HTML in content

| Field | Value |
| --- | --- |
| Severity | Low (author-trusted personal site) / Medium if untrusted PRs are merged |
| Status | open |
| Source | Manual (`config.yaml`, theme `layouts/partials/article/components/content.html`, About page HTML, `enableInlineShortcodes: true`, theme `readfile` shortcode `readFile \| safeHTML`) |
| Evidence | `markup.goldmark.renderer.unsafe: true` is required for existing posts (e.g. About, hermeticity essay `<style>` / `<div>`). Theme wraps `.Content` in `safeHTML`. `{{< readfile >}}` is used for SVG icons. KaTeX `trust` allows `\\htmlId` and `\\href` (theme math partial + site footer). |
| Why it matters | There is no HTML sanitizer between markdown and the published origin. A merged PR that adds `<script>` or a javascript: URL becomes XSS for every visitor. Contributor surface is currently small; comments are disabled. |
| Recommendation (advisory) | Keep treating PRs as untrusted. If the site ever takes outside contributions, turn `unsafe` off or sanitize, and review shortcodes. Leaving `unsafe: true` for existing author HTML is a product choice, not a scanner miss. |
